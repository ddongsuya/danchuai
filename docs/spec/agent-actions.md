# 단추 에이전트 사양서: 액션 등록부와 기관 비서

2026-11-19. 기관 비서 기능 지도 1~3단계 구현 기준. 사용자 결정: 기관 안의 기록은 승인 없이 바로 실행하고 되돌리기와 실행 기록을 붙인다.

## 1. 원칙

- 단추의 모든 기능을 **액션** 하나씩으로 적는다(단추 `lib/agent-actions.ts`). 화면 버튼과 비서가 같은 웹 처리(단추 웹 라우트)를 부른다.
- 단추에 액션 한 줄을 더하면 에이전트가 `GET /api/agent/actions`로 읽어 비서 도구·확인 카드에 붙인다. 에이전트 코드를 고치지 않아도 된다.
  - 바로 실행 액션 중 `tool: true`는 비서 도구가 된다.
  - 승인 액션(`confirm`)은 확인 카드(보내기 장부)로 받는다.
- 단추가 원장이다. 되돌리기 값과 실행 기록 원본은 단추(`agent_action_log`)에만 둔다. 에이전트 DB(`assist_runs`)에는 액션 이름·결과·단추 기록 id만 둔다.

## 2. 실행 수준

| 수준 | 뜻 | 누가 언제 | 기록 |
|---|---|---|---|
| read | 읽기, 요약 | 바로 | 남기지 않음 |
| auto | 기관 안의 기록(고객관리·할 일·일정, 견적 임시 저장) | 바로. 사람이 실행 카드에서 "되돌리기" | 단추 `agent_action_log`(되돌리기 값 7일) + 에이전트 `assist_runs` |
| confirm | 기관 밖으로 나가는 일(질의·답변·제출·선정·접수·계약 보고·단가표 반영) | 사람이 확인 카드에서 승인한 정확한 본문만, 한 번 | 보내기 장부(초안·승인·전송) + 단추 `agent_action_log` |
| human | 사람만(지우기, 최종 가격 승인, 계약 체결) | 단추 화면에서 사람 | 목록에만 적고 에이전트로는 실행하지 않음(403 `human_only`) |

## 4. 기관 비서 대화 (mode `assist`)

- 받은 요청함 아래 "비서" 버튼에서 연다. 기관 담당자만 쓸 수 있고, 같은 사람의 비서 대화는 이어서 쓴다.
- 턴마다 단추에서 액션 목록·브리핑·이번 주 보고를 읽어 맥락에 붙인다. 한 턴은 응답 한 번이다.
- 비서는 대상을 브리핑 번호(D·T·E·C·P·M)로 고른다. 에이전트가 그 번호를 id로 바꾼다. 목록에 없는 번호, 종류가 다른 번호, 틀린 값은 실행하지 않는다.
- 한 턴에 실행하는 액션은 최대 5개다. 결과는 실행 카드로 보인다. 카드 상태는 완료, 거절됨, 결과 확인 필요, 실행 안 함 가운데 하나이고, 되돌리기 버튼이 붙는다.
- 맥락에 넣지 않는 것: 금액, 단가, 합계, 이메일, 전화. 보고 숫자는 단추가 계산한 개수와 비율만 넣는다.
- 찾기 도구(읽기 + tool, 기관 범위): 비서가 찾을 말만 정한다. 서버는 단추를 읽지 않고 lookup 이벤트를 보내고, 앱 찾기 카드가 단추를 직접 읽는다. 결과는 모델 맥락·대화 기록에 없다. 한 턴에 최대 두 장.
- 회의 메모·녹음 전사본은 미팅 기록 한 건과 할 일(최대 네 개)로 남긴다. 전사본의 금액은 옮기지 않는다.

## 5. 되돌리기

- 시킨 사람만, 7일 안에, 그 뒤 아무도 그 행을 고치지 않았을 때만 되돌린다(`updated_at` 비교).
- 되돌리는 방식은 셋이다.
  - 만든 것은 지운다.
  - 고친 것은 바뀐 칸만 이전 값으로 돌린다.
  - 안건 단계는 이전 단계로 돌리고, 이력을 한 줄 남긴다.
- 두 번 되돌리지 않는다. 먼저 표시하고 실행하며, 실패하면 표시를 푼다.
- 7일이 지나면 매일 예약 작업이 되돌리기 값(`before`)을 비운다. 기록 줄은 남는다.

## 6. 개인정보·보안

- 기관 간 격리: 단추가 토큰으로 기관을 정하고, 모든 CRM 쿼리는 `org_id`로 거른다. 비서 대화와 실행 기록도 작업 공간(`org_id`)과 사람(`user_id`)으로 나눈다.
- 실행 기록에는 프롬프트·본문을 넣지 않는다. 처리방침 3항("탈퇴하거나 철회할 때까지")을 따른다.
  - 탈퇴하면 단추 기록이 계정과 함께 지워진다.
  - 동의를 철회하면 단추 기록은 `lib/agent-purge.ts`가 지운다.
  - 에이전트 `assist_runs`는 삭제 요청(purge)에 넣어야 한다. PR #29의 삭제 처리에 함께 넣는다.
- 바로 실행 경로(`/v1/danchu/run`·`runs`)도 국외 이전 동의 뒤에만 연다.

## 7. 4단계 (2026-11-20)

- 됨: 견적 금액 다시 계산(quote_price, 견적서 툴 계산), 견적서 만들기(quote_doc), 과거 견적 찾기(quote_history), 팀 넘기기(deal_assign), 결재 요청(approval_request), 회의 메모 → 기록·할 일.
- 결재는 할 일로 다룬다(결재자 할 일, 끝냄 = 결재). 반려·결재선이 필요하면 단추에 결재 표를 따로 만든다.
- 계약서(안): 단추가 선정된 견적(금액 그대로)·기관·의뢰자 정보·기관 양식 특약으로 볼 때마다 만든다(저장 없음). 기관은 PDF로 저장하거나 확인 카드로 의뢰자에게 보낸다. 전자서명은 하지 않는다(사용자 결정).
- 녹음 전사: 앱이 녹음을 Deepgram(미국, nova-3 ko, 학습 제외)에 바로 보내고 서버는 임시 토큰만 발급한다. 녹음마다 참석자 동의 확인. 전사본은 그 턴에만 모델에 붙이고 저장하지 않는다. 단추 처리방침 개정안(2026-12-17 시행)에 위탁·국외 이전을 넣었다.
- 의뢰자 견적서 보기: 기관이 견적서 툴로 만든 견적서가 제출 금액과 같으면 비교표가 열린 뒤 의뢰자가 기관 양식으로 본다.
- 견적 제출은 견적서 기준(2026-11-20, 단추 #141·#142): 확인 카드가 단추 제출 미리보기의 금액을 그대로 보이고 견적서 판과 함께 제출한다. 사람이 본 금액만 나간다(규칙 1). 견적서에 금액이 없는 줄은 카드에서 견적서에 넣고, 설계 변경·시험 추가는 견적서 툴에서 한다. 제출하면 서버가 승인한 줄 금액을 대화 초안에 옮겨, 다시 열었을 때 견적서가 바뀌었으면 다시 제출할 수 있게 한다.
